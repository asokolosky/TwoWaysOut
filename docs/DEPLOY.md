## Deploy

The app ships as one Docker image. The build downloads the Analyze Boston datasets (~450 MB),
builds `data/boston.sqlite`, and throws the raw files away before the final stage, so the first
build takes several minutes.

### Build the data locally (no Docker)

```bash
scripts/build_data.sh                  # fetch all five datasets + preprocess, uses .venv/bin/python
scripts/build_data.sh --python python3 # any other interpreter
```

Data Commons area housing (optional) needs a free key from https://apikeys.datacommons.org.
`build_data.sh` doesn't read `.env`, so pass the key to the command. To use the key from `.env`
without printing it:

```bash
DATACOMMONS_API_KEY="$(grep -E '^DATA_COMMONS_API_KEY=' .env | cut -d= -f2-)" scripts/build_data.sh
```

The app never calls Data Commons at runtime; the figures are stored in `boston.sqlite`.

### Local Docker

```bash
docker build -t twowaysout .
docker run -p 8000:8000 \
  -e DASHBOARD_PASSWORD=... \
  -e SESSION_SECRET=... \
  -e ANTHROPIC_API_KEY=... \
  -v twowaysout-data:/data \
  twowaysout
```

To include the optional Data Commons (U.S. Census) area context, pass the key as a BuildKit
secret. It's read only by the builder's data step and never stored in an image layer, build arg,
or env var. Without it the build skips area context.

```bash
docker build --secret id=datacommons_api_key,src=/path/outside/repo/datacommons_api_key -t twowaysout .
```

Passing secrets with `-e` puts them in your shell history; `--env-file` with a file outside the
repo (never baked into the image) avoids that. Open http://localhost:8000 and check http://localhost:8000/health. Generate a session secret with
`python -c "import secrets; print(secrets.token_urlsafe(48))"`.

- `ANTHROPIC_API_KEY` is optional; without it the app uses the rule-based "Basic analysis".
- The image sets `FORCE_SECURE_COOKIES=true`. Browsers accept Secure cookies on
  `http://localhost`, but if you test on another plain-HTTP host the town login won't stick;
  add `-e FORCE_SECURE_COOKIES=false` for that run only.
- `/data` holds `app.sqlite` (tenant reports, inspection statuses). The named volume keeps it
  across container restarts. `data/boston.sqlite` is read-only inside the image.
- `PORT` overrides the listen port (default 8000).
- `FORWARDED_ALLOW_IPS` lists the proxies allowed to set `X-Forwarded-For` (see "Client IPs
  behind a proxy" below). Locally there is no proxy, so leave it unset.

### Render

1. Push the repo to GitHub (the Dockerfile, `render.yaml`, and `.dockerignore` must be committed).
2. In Render: New > Blueprint, pick the repo. Render reads `render.yaml` and creates a Docker web
   service with a 1 GB disk at `/data` and a health check on `/health`.
3. When prompted, enter `ANTHROPIC_API_KEY` and `DASHBOARD_PASSWORD`. `SESSION_SECRET` is
   generated by Render. Leave `FORWARDED_ALLOW_IPS` empty for the first deploy, then set it as
   described below.
4. Wait for the first build (data download + preprocessing), then check that `/health` returns
   `{"status": "ok"}`. `/health` doesn't say which features are configured: confirm the AI by
   running `/check?sample=1` (no "Basic analysis" badge) and the dashboard by opening
   `/town/login` (sign-in form, not "Dashboard isn't configured").
5. Optional Data Commons area context: in the service's Environment settings add a secret file
   named `datacommons_api_key` whose contents are the key, then redeploy. Render builds with
   BuildKit and exposes each secret file to the build as a secret mount with the file name as
   its ID ([Render: Using Secrets with Docker](https://render.com/docs/docker-secrets)).
   Don't add it as an environment variable: Render passes env vars to Docker builds as build
   args, which the Dockerfile doesn't use for secrets. Render also copies secret files into
   the build context root; `.dockerignore` excludes `datacommons_api_key` so no `COPY` picks
   it up. Without the secret file, area context is skipped and everything else works.

### Client IPs behind a proxy

The report and login rate limiters key on the client IP (kept in memory only, hashed). uvicorn
runs with `--proxy-headers --forwarded-allow-ips="${FORWARDED_ALLOW_IPS:-127.0.0.1}"`, so it
takes the client IP from `X-Forwarded-For` only when the connection comes from a listed proxy.
Trusting every peer (`*`) would let anyone who can reach the port pick the IP the limiters see.
The value is a comma-separated list of IPs or CIDR ranges (uvicorn 0.31.0 and later accept
networks; this project pins 0.54.0).

On Render, the load balancer terminates TLS and forwards requests to the service
([Render: Web Services](https://render.com/docs/web-services)). Render doesn't publish the
address range those requests come from, so `render.yaml` leaves `FORWARDED_ALLOW_IPS` for you to
set (`sync: false`). Until it's set, every visitor appears to come from Render's proxy, so all
visitors share one report limit (5 per hour by default) and one login limit. To find the range,
open the service Shell while loading a page in a browser and list the networks of the peers
connected to the app port. Run this only in the Render Shell, where every peer is Render's
proxy. Anywhere clients connect directly (local Docker, a public port) the peers are visitors,
so it prints only /16 prefixes, never full addresses:

```bash
python -c "import os,socket,struct; p=int(os.environ.get('PORT','10000')); print(sorted({'.'.join(socket.inet_ntoa(struct.pack('<I', int(f[2].split(':')[0], 16))).split('.')[:2])+'.0.0/16' for f in (l.split() for l in open('/proc/net/tcp').readlines()[1:]) if int(f[1].split(':')[1], 16) == p and f[3] == '01'}))"
```

It reads IPv4 connections only. If it prints nothing, the proxy may connect over IPv6
(`/proc/net/tcp6`).

Set `FORWARDED_ALLOW_IPS` to the smallest private range that covers them (for example the
`/16` they share), redeploy, and check that the addresses stay in that range across a few
deploys. Never set it to `*`. Secure cookies don't depend on this setting: the image sets
`FORCE_SECURE_COOKIES=true`.

Persistent disks need a paid instance (the blueprint uses `starter`). On the free plan, remove
the `disk` block; `app.sqlite` then resets on every deploy or restart. The container runs as a
non-root user (uid 10001); if the mounted disk isn't writable by it, reports fail to save, so
check one report submission after the first deploy.

### Seed simulated demo data

Simulated reports live only in the `simulated_reports` table (ward + rental type, no addresses)
and are shown in their own SIMULATED section.

- Automatically: set `SEED_SIMULATED=1` at runtime (`docker run -e SEED_SIMULATED=1 ...`; the image
  default is `0`). On start, `docker/entrypoint.sh` seeds only if the simulated table is empty.
  `render.yaml` sets it to `1`.
- Try the entrypoint locally without Docker:
  `env APP_DB_PATH=/tmp/twowaysout-entry.sqlite SEED_SIMULATED=1 PORT=8797 sh docker/entrypoint.sh`
  (uses `.venv/bin/python` when present).
- Manually: `docker exec <container> python -m scripts.seed_reports --db /data/app.sqlite`
  (Render: run the same command from the service Shell). Re-running replaces all simulated rows.
- Locally without Docker: `.venv/bin/python -m scripts.seed_reports`.

### Privacy notes

- Raw downloads (owner names, mailing and contact addresses) exist only in the builder stage
  and are deleted there. The final image copies only the preprocessed `data/boston.sqlite`,
  which is built from whitelisted columns. `.dockerignore` keeps local `data/raw`, local
  databases, `.env`, `.git`, `.venv`, and `tests` out of the build context.
- uvicorn (started by `docker/entrypoint.sh`) runs with `--no-access-log`, so request lines with client IPs and paths are never
  logged. `--proxy-headers` with `FORWARDED_ALLOW_IPS` lets the app see the real client IP in
  memory for rate limiting, only from trusted proxies.
- The runtime image copies only `app/`, `samples/`, the entrypoint, and the two `scripts/` files
  start-up needs (`__init__.py`, `seed_reports.py`). The data pipeline stays in the builder.
- Secrets come only from runtime environment variables. Nothing sets them in the Dockerfile,
  `.env` is never copied, and `render.yaml` marks them `sync: false` or `generateValue: true`.
- `/health` returns only `{"status": "ok"}`. It doesn't reveal which features are configured.
